## Контекст и цель

В многопоточном программировании паттерн Producer-Consumer (Производитель — Потребитель) является одним из базовых способов организации взаимодействия между потоками. Одни потоки генерят данные (задачи, кадры, сетевые пакеты), а другие их обрабатывают. Для их связи требуется потокобезопасная очередь (Thread-safe Queue).
Ваша задача — реализовать шаблонный класс ограниченной потокобезопасной очереди ThreadSafeQueue<T>, поддерживающий безопасную параллельную запись и чтение множеством потоков одновременно (MPMC — Multi-Producer Multi-Consumer).
## Требования к функциональности

1. Синхронизация и защита данных:

         Все операции над внутренним контейнером должны защищаться мьютексом (std::mutex).
         Нельзя допускать состояния гонки (Data Race) и обращений к невалидной памяти.

2. Блокирующий pop (Условие опустошения):

        Если очередь пуста, вызов pop должен блокировать вызывающий поток (переводить его в состояние ожидания без использования холостых циклов while(true)).
        При появлении элемента поток должен просыпаться и забирать его.
        Обязана быть обработка ложных пробуждений (spurious wakeups) через передачу предиката в condition_variable::wait.

3. Ограничение по размеру / Bounded Queue (Условие переполнения):

        Очередь инициализируется с максимальной вместимостью capacity.
        Если очередь заполнена (size() == capacity), вызов push должен блокировать вызывающий поток до тех пор, пока в очереди не появится свободное место после вызова pop.

4. Завершение работы (Graceful Shutdown / Interruption):

        Метод shutdown() переводит очередь в состояние завершения: прекращается приём новых элементов, а все заблокированные на push и pop потоки разблокируются.
        pop при остановленной очереди должен возвращать false (или сигнальное значение), если элементов больше нет.

5. Оптимизация производительности:

        Передача данных должна поддерживать rvalue-ссылки (Move-семантику) для предотвращения лишнего копирования тяжелых объектов.
